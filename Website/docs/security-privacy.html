数据存储Storage主机信任Host trust隐私控制Privacy controls诊断Diagnostics

ServerDash 在本机保存机器和工作区数据，但不会把所有内容放在同一个存储中。凭据进入 Keychain，配置进入 SwiftData；Mac 与移动端使用独立数据库和独立 Keychain，不使用 CloudKit。ServerDash stores machine and workspace data locally, but not in one store. Credentials go to Keychain and configuration to SwiftData. Mac and mobile use independent databases and Keychains, without CloudKit.

SwiftData 使用版本化 V1–V5 Schema。升级前备份数据库；迁移失败时不会自动清空或重建。删除应用、数据库或 Keychain 项可能分别影响不同数据。SwiftData uses versioned V1–V5 schemas. Databases are backed up before upgrade, and migration failure does not automatically clear or rebuild them. Deleting the app, database, or Keychain items can affect different data independently.

SSH 主机信任SSH host trust

  • macOS 使用应用专属 known_hosts；移动端原生引擎按主机与端口保存信任。macOS uses an app-specific known_hosts; the mobile native engine stores trust by host and port.
  • 首次使用、显式复核或主机密钥错误恢复时才进入指纹确认。Fingerprint review appears on first use, explicit revalidation, or host-key error recovery.
  • 未知与变化的密钥都暂停连接；没有全局接受所有主机模式。Unknown and changed keys both pause connection; no global accept-all mode exists.
!
信任确认不是在线身份服务Trust confirmation is not an online identity service

ServerDash 展示服务器提供的指纹，用户仍需通过独立可信渠道核对。地址可达或 SSH 测试成功不等于身份已经可信。ServerDash shows the fingerprint offered by the server; users must verify it through an independent trusted channel. Reachability or a successful SSH test does not establish identity.

隐私控制Privacy controls

隐藏 IPHide IP addresses

隐私模式会覆盖界面、Markdown 导出与诊断中的 IP。编辑连接或核对主机信任时仍需显示真实地址，避免用户在错误目标上操作。Privacy mode masks IP addresses in UI, Markdown exports, and diagnostics. Connection editing and host-trust review still show real addresses to prevent actions against the wrong target.

公网 IP 与位置查询Public IP and location lookup

默认关闭，只有阅读说明并明确选择加入后才启用。查询由受管服务器访问 ipinfo.io；关闭后会清除 ServerDash 的内存位置缓存。Disabled by default and enabled only after explained opt-in. The managed server contacts ipinfo.io; disabling the feature clears ServerDash's in-memory location cache.

AI

终端上下文逐连接授权并只在发送时采集。聊天在本地保存不代表请求数据不出设备；实际数据会发送到用户配置的提供商。Terminal context is authorized per connection and captured only when sending. Local chat storage does not keep request data on-device; requests go to the configured provider.

事件日志与脱敏诊断Event logs and redacted diagnostics

OSLog 按 App、Data、SSH、Monitoring、Terminal、SFTP 分类。每台服务器保留独立事件日志，并提供可预览、可复制的 SSH Diagnostics。OSLog uses App, Data, SSH, Monitoring, Terminal, and SFTP categories. Each server has its own event log and previewable, copyable SSH Diagnostics.

  • 诊断路径不应记录密码、私钥、口令、命令正文、主机指纹或终端输出。Diagnostic paths should not record passwords, keys, passphrases, command bodies, host fingerprints, or terminal output.
  • 性能 Signpost 使用固定名称，不附带主机、用户、路径或命令元数据。Performance signposts use fixed names without host, user, path, or command metadata.
  • 复制前仍应预览诊断内容，并根据自己的环境再次检查。Preview diagnostics before copying and review them again for your own environment.

脱敏降低风险，但不是绝对保证Redaction reduces risk, not guarantees it

用户提供的名称、备注和远端输出可能包含未被识别的敏感信息。分享前应人工检查。User-provided names, notes, and remote output may contain unrecognized sensitive information. Review before sharing.
